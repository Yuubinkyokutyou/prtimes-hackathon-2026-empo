# PR Compass — 仕組みの簡単な説明

## 1. 何をするサービスか

PR Compassは、企業が過去に投稿したプレスリリースをもとに、次に発信できそうな新しい切り口を提案するサービスです。

同じ商品やサービスでも、発信方法にはさまざまなパターンがあります。

- 新商品・新サービス
- 導入社数や利用者数の節目
- 周年
- 顧客の導入事例
- 独自調査
- 他社や地域との提携
- 開発背景や舞台裏

過去に「新商品発売」として発信済みでも、次は「導入100社」「提供開始1周年」「顧客事例」など、別のニュースとして展開できる可能性があります。

このサービスは、プレスリリース本文を書くのではなく、次に検討する企画の切り口と参考事例を提示します。

## 2. MVPの使い方

1. 架空企業を1社選ぶ
2. その企業の投稿済みプレスリリースを自動分析する
3. まだ使っていない切り口を3件表示する
4. 各提案に、参考となる他社リリースを表示する

ユーザーによる条件入力はなく、企業を選ぶだけで結果が表示されます。

## 3. 表示する情報

各提案は、次の組み合わせで表示します。

```text
自社の投稿済みプレスリリース
        ＋
まだ使っていない発信の切り口
        ＋
参考にできる他社プレスリリース
```

例：

```text
自社PR:
「広報AIアシスタントのβ版を提供開始」

新しい切り口:
「導入社数・利用者数の節目」

参考事例:
「中小企業50社との共同実証を開始」
```

提案画面では情報量を抑え、企画判断に必要な情報だけを表示します。

## 4. 検索の仕組み

### 4.1 プレスリリースをベクトル化

タイトル、サブタイトル、リード文、本文、カテゴリ、キーワードなどをまとめ、プレスリリースごとの検索用文章を作ります。

その文章を埋め込みモデルで数値の配列（ベクトル）に変換します。

```text
プレスリリース本文
    ↓ 埋め込み
[0.12, -0.08, 0.34, ...]
```

文章の意味が近いプレスリリースほど、ベクトル同士の距離も近くなります。

### 4.2 pgvectorで類似事例を検索

PostgreSQLの拡張機能である `pgvector` を使い、対象企業の投稿履歴と意味が近い他社リリースを検索します。

検索ではcosine距離を利用します。

```sql
ORDER BY embedding <=> query_vector
```

検索時には次のデータを除外します。

- 対象企業自身のプレスリリース
- 公開日が設定されていないもの
- 未来の公開日になっているもの

### 4.3 類似度を再調整

ベクトル類似度だけでなく、次の情報も加えて候補を並べ替えます。

- 業種が同じか
- カテゴリが近いか
- キーワードが近いか
- リリース種別が近いか
- 発表時期が近いか

同じ企業や同じ種類の事例ばかりにならないよう、候補の多様性も調整します。

閲覧数や「いいね」数は参考情報として扱い、類似順位には加えていません。

## 5. 発信パターンの選び方

PR TIMESの既存事例から事前に整理した発信パターンを、パターンカタログとして管理します。

MVPでは12種類を登録しています。

1. 導入社数・利用者数の節目
2. 周年・継続年数
3. 顧客・導入事例
4. 独自調査・業界データ
5. ビフォー・アフター実績
6. 提携・地域連携
7. 顧客参加型企画
8. 季節・記念日イベント
9. 地域・拠点展開
10. 人物・チームの専門性
11. ノウハウ・ガイド公開
12. 開発背景・舞台裏

対象企業がすでに使っているパターンを除き、次の要素から提案候補を選びます。

- 他社参考事例との意味的な近さ
- 自社の投稿履歴に適用できそうか
- その企業がまだ使っていない切り口か
- 同業だけでなく異業種からも新しい発想を得られるか

上位3件は、同じ種類に偏らないように選択します。

## 6. パターン選択とOpenAI

パターン選択は環境設定で、決定論的なローカルロジックとOpenAI Responses APIを切り替えられます。

```text
ローカル設定:
pgvector／ローカルベクトル検索
    ＋
事前定義パターンによるローカル選択
```

`PR_GENERATION_PROVIDER=openai`では、候補となるパターンと他社事例を先にサーバー側で絞り、OpenAI Responses APIに適用可能性を分析させます。

```text
OpenAI設定:
pgvectorで参考候補を絞る
    ↓
OpenAIが適用可能なパターンを選ぶ
    ↓
許可されたパターンIDと参考事例だけを画面へ返す
```

OpenAIに自由な事実を作らせるのではなく、サーバーが許可した候補IDの中から選択させます。strict JSON Schemaで候補IDと選定理由を受け取り、重複IDや候補外IDは拒否します。本文の生成はMVPの対象外です。

## 7. データについて

ハッカソンデモでは、6社の架空企業をログイン対象として用意しています。

- 各社の投稿済みリリースは3件
- 他社参考事例を含めて42件の架空リリース
- 企業名、人物、数値、URLはすべてデモ用

実在企業や実在人物の情報ではありません。

## 8. 主な構成

```text
ブラウザ画面
  web/index.html
  web/app.js
  web/styles.css
        ↓
推薦API
  POST /api/recommendations
        ↓
推薦ロジック
  src/pr_recommender/recommendations.py
        ↓
パターンカタログ
  src/pr_recommender/pattern_catalog.py
        ↓
類似検索
  src/pr_recommender/search.py
        ↓
PostgreSQL + pgvector
```

データベースなしでも、同梱した架空データとローカルベクトルを使って同じ画面フローを確認できます。

## 9. 起動方法

### DBなしのデモ

```powershell
python app.py
```

ブラウザで以下を開きます。

[http://127.0.0.1:8765](http://127.0.0.1:8765)

### PostgreSQLとpgvectorを使う場合

```powershell
docker compose up -d db
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[postgres]"

$env:PR_DATA_MODE = "postgres"
$env:PR_DATABASE_URL = "postgresql://hackathon:hackathon-local-only@127.0.0.1:55432/prtimes"
$env:PR_EMBEDDING_PROVIDER = "local"

.\.venv\Scripts\python.exe -m pr_recommender.indexer --provider local
.\.venv\Scripts\python.exe app.py
```

## 10. MVPで検証したいこと

- 過去の発信から提案されると、次のPR企画を考えやすくなるか
- 他社の具体的な参考リリースが、社内説明や企画判断に役立つか
- 新商品発表以外の切り口に気づけるか
- 広報担当者や営業担当者のネタ探し時間を減らせるか

この検証結果をもとに、パターン数、検索精度、OpenAIによる選択ロジック、年間PR計画へ段階的に拡張します。
