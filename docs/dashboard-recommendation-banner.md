# ダッシュボード・レコメンドバナー

## 概要

PR TIMES風ダッシュボードの最上部に、レコメンド機能への入口として企画候補を1件だけ表示するバナーです。

利用者が分析画面を探しに行かなくても、ダッシュボードを開いた時点で「次に何を発信するか」の具体案を確認でき、その案に対応するレコメンド画面へ直接移動できます。

## 表示ルール

判定には `GET /api/recommendations` が返す `meta.daysSinceLastPublished` を使います。

| 最終配信からの日数 | 表示する企画 | バナーから開く画面 |
| --- | --- | --- |
| 30日以上 | `existingSuggestions[0]`（過去記事活用の最有力候補） | `01 過去記事活用` |
| 30日未満 | `newOpportunities[0]`（未発信の新しい切り口の最有力候補） | `02 新しい切り口` |
| 配信日不明 | `newOpportunities[0]` | `02 新しい切り口` |

30日は当バナー固有の判定値で、`frontend/src/App.tsx` の `DASHBOARD_STALE_AFTER_DAYS` に定義しています。

既存のレコメンド画面が初期タブを選ぶ基準は、バックエンド設定 `RECOMMENDATION_STALE_AFTER_DAYS`（標準60日）のままです。ダッシュボードのバナーをクリックした場合は、バナー側の30日判定を優先して該当タブを開きます。

## 「最有力候補」の決まり方

バナーは既存レコメンドAPIの並び順を利用し、`existingSuggestions` の先頭1件を表示します。

- OpenAI利用時：提案と過去リリースのEmbedding類似度が高い順
- テンプレート生成時：過去リリースのページビューが高い順に作られた候補

バナー内は情報量を抑え、アイコン、「PR企画レコメンド」、レコメンド画面と同じ具体的な企画タイトル、詳細導線だけを表示します。判定理由、企画種別、着想元、概要は詳細画面に委ねます。

## 画面遷移

「詳しく見る」を押すと、アプリ内のページ状態をダッシュボードからレコメンドへ切り替えます。

- 過去記事活用案：左側の `01 過去記事活用` を選択状態にする
- 新しい切り口：右側の `02 新しい切り口` を選択状態にする

URLに `?companyId=<company_id>` がある場合、ダッシュボードと遷移先の両方で同じ企業を取得します。

## 読み込み・エラー時の動作

- 読み込み中は「次の発信アイデアを探しています」と簡潔に表示します。
- 判定前の誤遷移を防ぐため、読み込み中のCTAは無効です。
- API取得に失敗した場合は一般的な案内文を表示し、CTAは無効のままにします。
- APIリクエストは画面破棄時に `AbortController` で中止します。

## デザイン

- PR TIMES風ダッシュボードに馴染む、白に近い青の背景と小さな青いアイコンを採用
- 背景模様は薄い円形1点だけにし、余白を主体にした情報階層
- CTAは大きな塗りボタンにせず、控えめなテキストリンクとして表示
- 760px以下ではアイコンと本文を横並びに保ち、CTAを本文下へ配置
- 企画タイトルは長文でもレイアウトを崩さないよう省略表示

## 実装箇所

- `frontend/src/App.tsx`
  - `DashboardRecommendationBanner`：取得、30日判定、表示、CTA
  - `PrDashboard`：ダッシュボード上部への配置
  - `App`：レコメンド画面と初期レイヤーの受け渡し
  - `RecommendationApp`：バナー指定レイヤーの初期表示
- `frontend/src/styles.css`
  - `.pr-recommend-banner*`：バナーとレスポンシブスタイル
- `backend/src/recommendations.ts`
  - 日数算出、既存候補の生成・並び替え

## ローカルでの確認方法

worktreeでは、ポート競合を避ける専用コマンドを使います。

```bash
npm run dev:worktree
npm run dev:worktree:status
```

`dev:worktree:status` に表示されたFrontend URLを開きます。特定企業の分岐を確認する場合は、次の形式で企業IDを指定します。

```text
http://localhost:<frontend-port>/?companyId=<company_id>
```

終了時は、そのworktreeのコンテナだけを停止します。

```bash
npm run dev:worktree:down
```

## 現時点の制約

- ダッシュボード用に専用APIは設けず、既存のレコメンドAPIを利用しています。初回生成に時間がかかる企業では、バナーも生成完了まで読み込み表示になります。
- 画面遷移はReact内の状態切り替えです。ダッシュボード／レコメンドを表すURLパスはまだありません。
- フロントエンドの自動UIテスト基盤は未導入のため、分岐とレスポンシブは実ブラウザで確認しています。
