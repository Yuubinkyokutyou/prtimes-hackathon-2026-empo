# PR Compass MVP 仕様・要件定義

## 1. 目的

中小企業の広報担当者が「一度プレスリリースを出した後、次に何を発信すればよいかわからない」という状態を抜け出すため、投稿済みプレスリリースと他社事例を比較し、まだ使っていない発信の切り口を根拠付きで提案する。

このMVPは単一機能に絞る。

> 架空企業を1クリックで選ぶと、既存PR × 未活用パターン × 他社参考事例を3件表示する。

本文執筆、公開、効果分析、年間計画はMVPの主導線に含めない。

## 2. 背景と検証する仮説

- 仮説1: 広報担当者はPR企画を立てるための社内情報収集に時間がかかる。
- 仮説2: 一度発信した後に、同じ事業を別のニュースへ展開する方法がわからない。
- 補助仮説: 他社の具体例と「社内で集める情報」を同時に示すと、営業担当者が口頭で行っている提案をセルフサービス化できる。

提供データにインプレッション、CTR、反応本文がないため、「受け取り方」や因果的な改善点は本MVPでは検証しない。

## 3. 対象ユーザー

- 専任広報が0〜2名程度の中小企業
- 過去に1〜10件のプレスリリースを投稿済み
- 新商品発表の後に継続ネタを作れていない担当者

## 4. 画面フロー

1. デモログイン画面に架空企業を最大6社表示する。
2. ユーザーは企業カードの「この企業で見る」を1回押す。
3. サーバーが対象企業の投稿済みPR（新しい順に最大10件）を読み込む。
4. pgvectorで他社の類似事例を検索する。
5. 事前定義した12パターンのうち、対象企業が未活用のものを順位付けする。
6. 上位3件を「自社の既存PR ＋ 新しいアプローチ ＋ 他社参考事例」の形で表示する。

## 5. 機能要件

### FR-01 デモログイン

- ID・パスワードは要求しない。
- 企業名、業種、投稿件数を表示する。
- 選択操作は1クリックで完了する。
- すべての企業・人物・実績が架空であることを明示する。

### FR-02 履歴分析

- 対象企業の公開済みPRを最大10件利用する。
- タイトル、サブタイトル、リード、本文、業種、カテゴリ、キーワード、リリース種別を検索テキストに利用する。
- 自社のリリースは参考事例から除外する。
- 公開日時がないもの、未来公開のものは除外する。

### FR-03 未活用パターン提案

- 事前分析済みパターンは10〜100件の範囲で管理可能とし、MVPでは12件を登録する。
- 各パターンは最低1件の他社参考リリース複合キー（`company_id:release_id`）に紐づく。
- 既存PRで使用済みの大分類を除外する。
- 同じ大分類を上位3件に重複させない。
- 提案は企画の切り口までとし、本文や未確認の数値を生成しない。

### FR-04 根拠表示

各提案に以下を表示する。

- 起点にする自社の既存PR
- 新しく適用するパターン
- 適用できそうな理由
- 他社参考事例とベクトル類似度
- 社内で確認・収集する情報
- 提案が本文ではない旨の注意

## 6. 事前定義パターン

実装は `src/pr_recommender/pattern_catalog.py` を正とする。

1. 導入社数・利用者数の節目
2. 周年・継続年数
3. 顧客・導入事例
4. 独自調査・業界データ
5. ビフォー・アフター実績
6. 提携・地域連携
7. 顧客参加型企画
8. 季節・記念日イベント
9. 地域・拠点展開
10. 人物・チームの専門性
11. ノウハウ・ガイド公開
12. 開発背景・舞台裏

`src/pr_recommender/demo_proposals.json` には、OpenAI API未接続時の画面・シナリオ確認用として、別途6社分の静的な提案例を収録する。参考事例はデモコーパスにも登録する。

## 7. 選択ロジック

### 候補検索

PostgreSQLモードでは `pr_ai.release_embedding.embedding <=> query_vector` を使うpgvector cosine検索を行う。同業と異業種の候補を別々に確保し、自社、未公開、未来公開を除外する。

検索後の構造化再ランキングは以下を利用する。

| 特徴 | 重み |
|---|---:|
| 意味類似 | 0.55 |
| 同業種 | 0.15 |
| カテゴリ一致 | 0.10 |
| キーワード一致 | 0.08 |
| リリース種別一致 | 0.07 |
| 公開月の近さ | 0.05 |

閲覧数などの反響値は説明用に保持するが、類似順位には利用しない。

### パターン順位

API未接続のMVPでは次の決定論的スコアを使う。

| 特徴 | 重み |
|---|---:|
| 参考事例の再ランキングスコア | 0.55 |
| 自社履歴と適用語の一致 | 0.25 |
| 未活用であること | 0.15 |
| 異業種の新規性 | 0.05 |

### OpenAIへの切替方針

OpenAI API利用時も、入力候補はサーバー側で許可したパターンIDと参考リリースキーだけに限定する。Responses APIのstrict JSON Schemaで上位パターンID、理由、参照キーを返し、返却値が候補集合外ならエラーにする。APIキーだけでは外部送信を開始せず、環境変数で明示的にプロバイダーを切り替える。本文は送信・生成せず、公開済みPRの検索用要約と安全なメタデータだけを使う。

## 8. API

### `GET /api/bootstrap`

デモ企業、投稿件数、データモード、埋め込みプロバイダーを返す。

### `POST /api/recommendations`

入力:

```json
{"company_id": 900001, "limit": 3}
```

出力の主要項目:

```json
{
  "company": {},
  "analysis": {
    "release_count": 3,
    "catalog_size": 12,
    "vector_search": "local vector demo"
  },
  "own_releases": [],
  "recommendations": [
    {
      "pattern": "導入社数・利用者数の節目",
      "source_release": {},
      "reference_release": {"similarity": 0.81},
      "required_facts": []
    }
  ]
}
```

## 9. 非機能要件

- DBなしのローカルデモが追加依存なしで起動する。
- PostgreSQLモードではpgvectorを利用する。
- ダミーモードは外部通信しない。
- APIは同一オリジンのみ許可し、JSONサイズを制限する。
- APIキーやDBパスワードをソース・ログ・デモ画面に含めない。
- PCとスマートフォンの両方で主要導線が利用できる。

## 10. 受入条件

- 6社の架空企業が1クリックログインとして表示される。
- 各企業が1〜10件の投稿履歴を持つ。
- 選択後、追加入力なしで3件の提案が表示される。
- すべての提案に自社既存PRと他社参考事例が1件以上ある。
- 自社リリースが他社参考事例として表示されない。
- 使用済みの大分類が提案されない。
- 提案に社内で確認する情報が表示される。
- デモモードは外部APIキーなしで動作する。
- PostgreSQLモードの候補検索がpgvector cosine演算子を使用する。

## 11. MVP外

- プレスリリース本文の生成・校正
- PR TIMESへの投稿
- インプレッション、CTR、SNS感情の分析
- 実在企業向けの認証・権限管理
- 年間PR計画の画面提供
- パターンカタログを自動更新するオフライン分析基盤
